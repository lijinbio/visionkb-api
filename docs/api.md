# VisionKB API reference (v0.1)

Base path `/v1`, JSON only. The machine-readable schema is [`openapi.json`](openapi.json)
(also served at `/v1/openapi.json`, with an interactive page at `/v1/docs`).

Every response, success or error, is one envelope:

```json
{"status": "ok" | "error", "kg_release": "visionkb-YYYY.MM.N", "data": ..., "page": {"limit", "offset", "total"} | null,
 "warnings": ["..."], "error": {"code", "message"} | null}
```

- `kg_release` names the release every value came from; atlas rows also carry `dataset_version`.
- Lists: default `limit` 50, capped at 200 (`VISIONKB_MAX_ROWS`; a larger request is capped and a warning
  says so). A response aims at 24,000 characters at most: if a list would exceed it, it is cut from the
  end, `page` keeps the requested limit and total, and a warning gives the number returned, so page on
  with `offset`.
- Errors never fall back to invented data: unknown ids give `404 not_found`, malformed CURIEs
  `400 invalid_curie`, predicates outside Biolink 4.4.6 `400 unknown_predicate`, Biolink predicates
  that the release does not use `400 predicate_not_in_release`, request-schema problems `422
  invalid_request`, a down database `503 neo4j_unavailable` / `postgres_unavailable`.
- Auth: `Authorization: Bearer <token>`. Tokens live in `VISIONKB_API_TOKENS_FILE`, one
  `token<TAB>scopes` per line: a TAB between token and scopes, scopes separated by commas and/or spaces
  (`token<TAB>read`, `token<TAB>read,proposals:read`); `#` starts a comment; tokens have 16+ characters.
  Scopes: `read` (all GET endpoints except health/ready), `proposals:read`, `proposals:write`.
  `/v1/health` and `/v1/ready` need no token.
- The API reads only the release bundle directory (`VISIONKB_RELEASE_DIR`), Neo4j and PostgreSQL.
  Paths in dataset records (`h5ad_path`, `soma_uri`, `bind.path`) are metadata for clients that run
  where the data are; the service never opens them.

The examples below are real responses from the synthetic fixture release
(`tests/fixtures/make_fixture.py`: real HGNC/CL/UBERON/MONDO/EFO identifiers, **synthetic values**),
generated by `scripts/make_api_docs.py`. `$TOKEN` stands for a token with the needed scope.

## Health

`GET /v1/health`

Component status, no auth. HTTP 200 while the process serves the release; a component that is not ok is listed in `warnings`. `neo4j.kg_release` is read from the graph and must match the API's release (else status `mismatch`).

```bash
curl -s "$VISIONKB_API_URL/v1/health"
```

HTTP 200

```json
{
  "status": "ok",
  "kg_release": "visionkb-0000.01.0",
  "data": {
    "neo4j": {
      "status": "ok",
      "name": "Neo4j Kernel",
      "version": "2026.10.1",
      "edition": "community",
      "kg_release": "visionkb-0000.01.0"
    },
    "summaries": {
      "status": "ok",
      "n_rows": 80
    },
    "postgres": {
      "status": "ok",
      "server_version": "17.11 (Debian 17.11-1.pgdg13+2)",
      "schema_version": 1
    },
    "release": "visionkb-0000.01.0",
    "version": "0.1.4"
  },
  "page": null,
  "warnings": [],
  "error": null
}
```

## Ready

`GET /v1/ready`

Readiness, no auth (container HEALTHCHECK, Kubernetes readiness probe). HTTP 200 only when the release is loaded and neo4j, summaries and postgres are all ok; otherwise HTTP 503 with `status: error`, `error.code` `not_ready`, the failing components in `error.message` and `warnings`, and the same component status in `data` as `/v1/health`.

```bash
curl -s "$VISIONKB_API_URL/v1/ready"
```

## get_relationships

`GET /v1/relationships?subject=&object=&predicate=&object_category=&knowledge_level=&species=&limit=&offset=`

Edges from `subject` and/or to `object` (at least one is required). `predicate` must be a Biolink 4.4.6 predicate used in the release. `species` matches `species_context_qualifier`, or the nodes' `in_taxon` for edges without one. Ranked by `evidence_count`, then `max_pct_expressing`. `publications` holds at most 5 (`n_publications` gives the count); `summary` carries the expression edge summary properties. Rejected edges are never returned.

`GET /v1/gene-sets?entity=&kind=&dataset=&min_pct=&descendants=&limit=&offset=`

`kind=expressed` (default for CL / CellState): genes with `expressed_in` edges to the entity, or to its `subclass_of` descendants up to 3 hops (`descendants=false` to switch off). Default `sort=specificity`: score = (pseudobulk_cp10k of the supporting group + 1) / (max pseudobulk_cp10k of the gene over the OTHER groups of the same dataset and level + 1; pseudocount 1 CP10k as in log1p(CP10k)), best StudyResult per gene, ties by pct_expressing; each item has `score_kind`, `pct_expressing` and `best_study_result` (group, its pseudobulk, the other-group max and that group); the definition is also in `warnings`. `sort=pct` keeps the v0.1.2 ranking (max `pct_expressing`). With `dataset`, only StudyResults of that dataset count; `min_pct` filters StudyResults. Expression edges follow the release's `expression_edge_rule` (manifest; D18: pct_expressing >= 0.10 and n_cells >= 20, pseudobulk >= 0.10 x the gene's max in the same dataset and level, n_donors_expressing >= 2; majorclass/celltype only), quoted in a warning on every `kind=expressed` answer (older releases without the field: D8 text); the full gene x group table is `/v1/atlas/expression`. `kind=disease_genes` (default for MONDO / HP): genes with `gene_associated_with_condition`, `causes`, `contributes_to`, `genetically_associated_with`, `has_phenotype` or `associated_with` edges to the entity or its descendants, scored by edge count.

## Proposals (write-back)
