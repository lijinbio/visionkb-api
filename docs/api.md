# VisionKB API reference (v0.1)

Base path `/v1`, JSON only. The machine-readable schema is [`openapi.json`](openapi.json)
(also served at `/v1/openapi.json`, with an interactive page at `/v1/docs`).

Every response, success or error, is one envelope:

```json
{"status": "ok" | "error", "kg_release": "visionkb-YYYY.MM.N", "data": ..., "page": {"limit", "offset", "total"} | null,
 "warnings": ["..."], "error": {"code", "message"} | null}
```

- `kg_release` names the release every value came from; atlas rows also carry `dataset_version`.
- Lists: default `limit` 50, capped at 200 (`VISIONKB_MAX_ROWS`; a larger request is capped and a warning
  says so). A response aims at 24,000 characters at most: if a list would exceed it, it is cut from the
  end, `page` keeps the requested limit and total, and a warning gives the number returned, so page on
  with `offset`.
- Errors never fall back to invented data: unknown ids give `404 not_found`, malformed CURIEs
  `400 invalid_curie`, predicates outside Biolink 4.4.6 `400 unknown_predicate`, Biolink predicates
  that the release does not use `400 predicate_not_in_release`, request-schema problems `422
  invalid_request`, a down database `503 neo4j_unavailable` / `postgres_unavailable`.
- Auth: `Authorization: Bearer <token>`. Tokens live in `VISIONKB_API_TOKENS_FILE`, one
  `token<TAB>scopes` per line; scopes `read` (all GET endpoints except health), `proposals:read`,
  `proposals:write`. `/v1/health` needs no token.
- The API reads only the release bundle directory (`VISIONKB_RELEASE_DIR`), Neo4j and PostgreSQL.
  Paths in dataset records (`h5ad_path`, `soma_uri`, `bind.path`) are metadata for clients that run
  where the data are; the service never opens them.

The examples below are real responses from the synthetic fixture release
(`tests/fixtures/make_fixture.py`: real HGNC/CL/UBERON/MONDO/EFO identifiers, **synthetic values**),
generated by `scripts/make_api_docs.py`. `$TOKEN` stands for a token with the needed scope.

## Health

`GET /v1/health`

Component status, no auth. HTTP 200 while the process serves the release; a component that is not ok is listed in `warnings`. `neo4j.kg_release` is read from the graph and must match the API's release (else status `mismatch`).

```bash
curl -s "$VISIONKB_API_URL/v1/health"
```

## search_entities

## get_relationships

`GET /v1/relationships?subject=&object=&predicate=&object_category=&knowledge_level=&species=&limit=&offset=`

Edges from `subject` and/or to `object` (at least one is required). `predicate` must be a Biolink 4.4.6 predicate used in the release. `species` matches `species_context_qualifier`, or the nodes' `in_taxon` for edges without one. Ranked by `evidence_count`, then `max_pct_expressing`. `publications` holds at most 5 (`n_publications` gives the count); `summary` carries the expression edge summary properties. ## get_gene_set

`GET /v1/gene-sets?entity=&kind=&dataset=&min_pct=&descendants=&limit=&offset=`

`kind=expressed` (default for CL / CellState): genes with `expressed_in` edges to the entity, or to its `subclass_of` descendants up to 3 hops (`descendants=false` to switch off), scored by max `pct_expressing`; with `dataset`, only StudyResults of that dataset count. The KG holds expression edges only where pct_expressing >= 0.10 and n_cells >= 20 (decision D8); lower thresholds need `/v1/atlas/expression`. `kind=disease_genes` (default for MONDO / HP): genes with `gene_associated_with_condition`, `causes`, `contributes_to`, `genetically_associated_with`, `has_phenotype` or `associated_with` edges to the entity or its descendants, scored by edge count.

```bash
curl -s -H "Authorization: Bearer $TOKEN" "$VISIONKB_API_URL/v1/gene-sets?entity=CL:0000573&kind=expressed&limit=2"
```

## Proposals (write-back)

`POST /v1/proposals  |  GET /v1/proposals?status=&limit=&offset=`

POST (scope `proposals:write`) validates a KGX-style edge: `subject`/`object` CURIEs with known prefixes, a concrete (not mixin/abstract) Biolink 4.4.6 predicate, `knowledge_level` and `agent_type` from the Biolink enums, an `infores:` primary source, PMID/DOI publications and Biolink qualifiers (flat, as in KGX, or under `qualifiers`). It stores the edge in PostgreSQL with status `proposed` and returns 201; the same `run_id` + edge returns the first proposal (200, `created: false`). Proposals never touch Neo4j; unknown subject/object are accepted with a warning. GET (scope `proposals:read`) lists the queue, newest first. Bodies are limited to 64 KiB.

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" "$VISIONKB_API_URL/v1/proposals" -d @proposal.json
```
